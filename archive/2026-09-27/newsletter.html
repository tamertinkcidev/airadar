Laut einer Ankündigung vom 13.08.2026 wird die alte Sonar-Chat-Completions-API am 27.09.2026 abgeschaltet und die bereits im August gestartete Agent API zur einzigen Schnittstelle. Preise sollen laut Ankündigung unverändert bleiben. Eine unabhängige Bestätigung, dass der Cutover heute tatsächlich stattgefunden hat, war aus unserer Umgebung nicht möglich (community.perplexity.ai blockiert) – vor einer Workflow-Umstellung den eigenen n8n-Perplexity-Node testen. Für Tinkellect-Workflows

Zwei Ansatzpunkte aus der Baseline bleiben unverändert relevant, dazu ein Hinweis zum n8n-Update dieser Woche:

  • Exposé-Extraktion – Gemini 3.8 Flash über den nativen 'Google Gemini Chat Model'-Node mit Vertex-EU-Region (Belgien/Niederlande) für DSGVO-konforme Verarbeitung von Objektdaten; Structured Output für feste Exposé-Felder nutzen.
  • Anfragen-Routing – GPT-6 Luna über den nativen OpenAI-Node für die Erstklassifikation von Anfragen (Kauf/Miete/Besichtigung) – bei hohem Volumen kaum spürbare Kosten. Tool-Calling funktioniert nur, wenn der Node intern die Responses API nutzt.
  • n8n-2.41.0-Update prüfen – Wer den MiniMax- oder Gemini/Qwen-Node im Einsatz hat: Modell-Dropdowns sehen diese Woche ggf. anders aus (MiniMax lädt jetzt live aus der API, Gemini/Qwen zeigen nur noch Chat-Modelle) – kein Handlungsbedarf, aber vor dem nächsten Deploy einmal prüfen.
n8n-Updates
n8n 2.41.0: MiniMax-Modelle jetzt dynamisch aus der API

Der MiniMax-Chat-Model-Node lädt die verfügbaren Modelle jetzt live von der API statt aus einer hartkodierten Liste – neue MiniMax-Modelle stehen automatisch zur Verfügung, ohne auf ein n8n-Update zu warten. Release Notes

n8n 2.41.0: Gemini- und Qwen-Dropdowns zeigen nur noch Chat-Modelle

Die Modellauswahl in den Google-Gemini- und Qwen-Cloud-Nodes filtert jetzt auf reine Chat-Modelle – Embedding- und andere Nicht-Chat-Modelle tauchen nicht mehr versehentlich in der Dropdown-Liste auf. Release Notes

n8n 2.41.0: OpenAI-Node akzeptiert Objekt-Werte für JSON-Parameter

Für JSON-typisierte Parameter im OpenAI-Node können jetzt direkt Objekte übergeben werden, statt sie vorher in einen String zu serialisieren – relevant für dynamisch gebaute Function-Call-Argumente. Release Notes
